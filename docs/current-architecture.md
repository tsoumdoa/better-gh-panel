# Current architecture

The padded header move target delegates mouse-down to Grasshopper so native dragging, selection and undo stay intact. Move/resize hover consumes the event after setting its cursor, preventing the host from replacing it. The resize target is 24 × 24 canvas units; the footer ends 28 units before the right edge to keep controls separate. Native host checks exercise header dragging and every padded corner in Full and Half layouts.

`CanvasRowRenderer` draws the fixed numbering gutter and aligns row text by font ascent against one canvas-unit baseline. Asc/Desc shows the one-based index into the current result beside the original branch item index in a smaller bracketed slot. Source order hides the secondary slot but keeps its space, and values retain the path column even when branch headings are grouped. Gutter capacity uses the full snapshot item count, which bounds every captured branch index, so paint never scans the tree or resizes columns based on filtered or scrolled rows. Numbering is transient presentation, adds no saved setting, and does not change selection identity, query order or typed output. Row hits retain the view number for tooltip lookup without searching the result. Numeric cells use right-aligned monospaced text; other data retains left alignment. Row height stays 17 canvas units. The native host checks cover digit-boundary filtering, row jumps beyond the viewport, selection retention, output invariance and the minimum Half layout.

Row selection is bound to a snapshot and uses source positions, with ranges and copy order taken from the current query result. New solutions clear selection; filtering removes hidden selections and sorting retains matching source positions. Actions reject obsolete snapshots, pending queries and stale row hit regions. Row and branch-heading clicks select without moving the camera. Double-clicking a row or branch heading clears selection, as do clicks on empty table, panel or canvas space. Double-clicking empty table space does not open search. Panel header clicks retain Grasshopper's component dragging behavior. While rows are selected, a canvas observer follows the host's ordinary blank-canvas selection gesture; it excludes other objects, widgets, wires and panning, and detaches when selection clears, the canvas changes documents or is disposed. Branch filters clear selection and only narrow the query. The explicit Frame selection context-menu action only moves the camera, using the same bounds resolver as preview, including custom preview goo. Clearing row selection also cancels pending copying and closes its action menu while retaining the filtered-result preview scope. Right-click actions retain an existing multi-row selection; value and geometry copying remain explicit context-menu actions.

`PanelGeometryHighlight` participates in the component's native Grasshopper preview callbacks. It borrows preview goo only for the current scope: selected positions in Selected mode, or the published query's complete `RowPositions` in Filtered results mode. Off clears the preview cache. No callback falls back to the base component's full-tree preview. Selected rows use Grasshopper's selected wire/material settings; other matches use normal colors even when the component itself is selected. Clipping bounds cover only the drawn scope and are empty when preview is off, hidden, locked or suspended. Selected wires receive Grasshopper's small clip-depth bias and configured thickening when the component has not already received them from the native selection pass; the drawing transform is restored afterward. This keeps upstream previews from covering the highlight without changing geometry or disabling depth testing. Other components' previews remain independent.

The header preview menu stays available in Full and Half layouts. `PanelPreviewMode` is saved as `PanelPreviewMode`, defaults to Selected for missing or unknown values, and records undo without expiring the solution. Reset retains the mode while clearing selection and filters. Query start, new solutions, saved-state reads, and document unload/removal clear borrowed previews. Query publication synchronizes selection and rebuilds the scope independently of painting, including offscreen matches; empty and failed queries draw nothing. Document switches clear selection, and reactivation restores the current filtered scope when appropriate. Repainting, sorting, filtering, selecting and switching preview modes never frame the camera. No preview operation bakes geometry or changes Rhino object selection.

`PanelQueryOptions.SearchMode` selects Text, Regex, Value, Length, Area or Volume while `Search` holds the text, pattern or comparison. The search dropdown reuses the existing compact canvas menu and inline editor. Text retains legacy numeric comparisons; explicit scalar modes support greater/less comparisons, equality and inequality. Regex runs against captured value text with case-insensitive, culture-invariant matching and time limits. Whitespace in regex patterns remains significant in both query execution and output-filter detection. Invalid expressions publish an error and disable stale row actions. Modes persist with the definition, default to Text for older files, and reset with the view.

Geometry filtering first validates the query and collects eligible branch/type/valid primary-metric candidates on a worker. The session measures those positions, including offscreen rows, through its existing single geometry worker, then captures an immutable measurement map on the UI thread for the final managed query. The query retains the original snapshot identity and source positions; cancellation and request ownership reject obsolete results. Metrics compare full-precision display-unit values using the same source-unit/dimension conversion guards as formatting. Length covers curves and circle circumference; area covers rectangles, surfaces and open Breps; volume covers boxes and closed Breps. Unsupported secondary metrics are excluded. Visible-row measurement and copying share the same cache and queue.

Value copying uses converted snapshot numbers or the geometry metric with matching unit/dimension conversion, without unit labels. Decimal formatting changes copied text without changing output precision. Explicit measurement batches share the session's single background worker with visible-row measurement, allowing offscreen selected rows to complete. Cancellation, new snapshots and session disposal resolve pending requests and prevent stale clipboard writes. Live source formatting and clipboard publication execute on Rhino's UI thread. Rows without a supported scalar metric retain their full text; unavailable measurements fail the whole value copy without replacing the clipboard.

Geometry copying duplicates supported geometry into a private 3DM archive with the source solution's model units and tolerance, then publishes the native Windows Rhino clipboard format. No objects are baked into or deleted from the user's Rhino document. Unsupported, invalid and non-geometric rows are skipped and reported. An empty supported selection leaves the clipboard untouched. Native Mac geometry clipboard and custom model units remain unsupported.

`BetterPanelComponent` applies saved tree tools in order: Simplify, Trim, Flatten, Reverse. Unit conversion follows the tree tools, then the current query filters the typed output. With all operations and filters off, it forwards Grasshopper's typed input tree unchanged. `PanelTreeOperations` copies paths and branch lists before changing structure, preserving typed goo and upstream data. Simplify removes shared path indices before Trim removes trailing path indices, merging coincident branches in source order; fully trimmed paths become `{0}`. The component owns a structural copy of the transformed tree and captures a presentation snapshot before filtering. Query row positions select typed goo from that same captured tree; matching branch paths preserve empty branches when no item filter is active. Output keeps transformed tree order independently of view sorting. A pending or failed filter outputs an empty tree. Query changes and completion schedule a normal Grasshopper solution to update downstream objects. An internal publication solve reuses the captured tree and query, avoiding repeated geometry calculation. Normal upstream expiration clears that reuse flag, cancels obsolete work and invalidates the UI before replacement input arrives. Snapshot identity, document ownership and request numbers guard scheduled output callbacks. `SnapshotCapture` caches primitive summaries and keeps live goo references in the component for full-value copying on the Rhino UI thread.

`BetterGhPanel.Core` owns immutable snapshots, query options, stable source positions, filtering, cancellable sorting, and scalar statistics. Query `RowPositions` indexes `Snapshot.Rows`; each row retains its path and original index within that branch. The canvas reads visible rows directly through these positions. Snapshots use object identity for ownership checks, without separate version or row/branch identity fields. The result also carries matching branch paths, including empty branches when browsing without item filters, for both statistics and typed output filtering.

`GeometryHints` captures analytic primitive measurements and stored properties as immutable `PanelGeometryInfo` records with raw values, dimensions and model units. Painting submits visible row positions to `PanelSession`; it never duplicates or measures geometry inline. After an initial 40 ms scrolling delay, a UI callback prepares a deep curve/Brep copy and one background operation computes general curve length/linearity, trimmed surface/open Brep area or solid Brep volume. The worker owns and disposes its copy and never accesses source goo or the Rhino document. Pending rows show measuring status; successful and failed results are cached by source position and repaint the panel without another query or solution. The queue continues without another scrolling delay for each row, while measurement redraws are coalesced over 60 ms. Each session runs at most one geometry operation. Only row bounds intersecting the canvas viewport enter the automatic pending queue; explicit copy batches can request offscreen rows. Scrolling and canvas panning replace that queue; offscreen panels and zooming below the row display threshold clear it. Canvas clipping does not change table layout or scroll capacity. Queued rows that leave view are skipped. A native mass-property call already running cannot be interrupted; it finishes and releases its copy, with stale publication rejected.

A normal new solution invalidates geometry cache entries; a unit-only solution retains completed and pending entries only when source goo identity, position and model units still match. Entry identity rejects stale callbacks across new solutions and disposal. Invalid, obsolete and disposed views cannot start geometry work. `PanelUnits.FormatGeometry` applies only conversions matching the model units and metric dimension, with decimal changes formatting cached raw values. Geometry output is never scaled. Invalid rows carry a captured validity reason and visible text label. Background filtering retains its existing behavior; asynchronous metrics do not enter text search. No live geometry enters the managed snapshot. McNeel's [asynchronous execution guidance](https://developer.rhino3d.com/guides/scripting/advanced-async/) describes the separation between background work and document/UI access.

`PanelGeometryInfo` separates its compact description from labeled tooltip details. The same summary builders capture pending metadata and construct measured results, so a metric augments the original trimming, degree, topology and count information. Curve linearity/planarity and single-face surface planarity are computed on the owned background copy. Rows keep the type, a few relevant properties and the metric; geometry rows do not repeat a separate type label. Tooltips show the formatted metric once, followed by labeled properties, including surface U/V degree and Brep face/edge/vertex counts. Pending and failed rows retain the available metadata, and unit/decimal changes reformat the metric without removing those details. Planarity uses RhinoCommon's default zero tolerance.

`PanelUnitOperations` converts Number and Integer values after tree tools using `PanelUnits` in the core. It copies paths and branch lists, creates full-precision Number goo, and preserves other items and empty branches. Modes distinguish length (mm ↔ m), area (mm² ↔ m²), volume (mm³ ↔ m³), and angle (rad ↔ deg). A footer dropdown opens upward and also exposes automatic or 0–12 decimal places. Decimal changes invalidate the canvas without recomputing the solution; rows, numeric copying, and statistics share formatting. Snapshots carry their conversion mode so formatting and filtering use the same units. Obsolete results are hidden while a newer query completes. Saved conversion and decimals default to off/automatic for older definitions and participate in undo. Query filters operate on the converted snapshot numbers; output precision is never changed by formatting.

One `PanelSession` per component owns the current snapshot, copied options, and the published result. `PanelQueryWork` gives managed queries a 120 ms UI time budget measured with a monotonic stopwatch, independent of row and branch count. Checkpoints cover empty-branch scanning, each row, sorting and result construction. When the budget expires, the same iterator continues on a worker with its scan position, statistics and merge-sort state intact; no partial result is published and no scan is restarted. Worker completion bypasses deadline checks and iterator handoffs inside the loops. The deadline is cooperative: individual string operations, allocations and copies can overrun it. Regex and geometry filters start in the background because a single operation cannot yield midway. `HasCurrentResult` gates rows, hit regions, counts, type summaries, statistics and tooltips. Pending views show Recomputing… with an animated spinner; the session owns its timer, runs it only for a visible busy panel, and stops it on completion or disposal. Disabled components invalidate their input into an idle suspended state, cancel pending work and stop animation. Their canvas shows Disabled until re-enabling supplies a new snapshot; query edits and late worker completions cannot restart them. Errors hide stale results too. Cancellation and request numbers reject obsolete results before UI publication. Changed options mark the document modified through `QueryChanged`; query progress and completion invalidate the canvas directly. Equal options do not trigger another scan. The component's reset path explicitly closes draft editors and clears transient canvas state, even when the query options are already at their defaults.

`BetterPanelAttributes` draws the canvas and handles tree tools, row interaction, scrolling, inline editing, and resizing. Tree tools expire the solution, record undo, clear branch selections when paths can change, and mark the definition modified. Search and filters also change typed output; sorting and decimal formatting affect only the view. The header Reset and Reset panel menu command restore all data settings in one undo step and recompute the original input when output tools were active. Reset also clears transient selection and scroll, closes dropdowns before menu hit handling, and cancels the component's owned text editor. Reset panel view and Reset tree tools remain separate context-menu commands. `CanvasMenu` owns compact dropdown layout, selection, hover and paging; its navigation row never overlaps selectable items. `CanvasPanelSize` owns dimension validation and presets. Selection and full-value lookup use snapshot positions with ownership checks. The modeless inspector and its row view were removed in `0.1.3-beta.1`.

Width and height are canonical saved settings. New panels use 360 × 360; existing dimensions and size presets retain their original behavior. Preset check marks are derived from dimensions. Serialization retains the legacy `PanelSize` key, and reads it as a fallback when dimensions are absent. Missing tree tool settings default to disabled, preserving older definitions' output. Document closure releases sessions; a tab switch closes the editor and clears automatic viewport measurement requests while retaining the snapshot and cache. An operation already running can finish. Automatic measurement resumes when the panel becomes visible; explicit filter batches may continue in the background, with viewport highlighting and camera framing suspended for the inactive document.

`CanvasPanelDisplay` is a separate saved presentation setting: Full uses the canonical height and Half derives half that height. One header chevron toggles Full ↔ Half. Display changes record undo and invalidate layout without solving or changing query options. Wire grips use the canonical full-size coordinates in both modes; the visible body uses a derived top offset. Resizing in Half maps the visible height back to the canonical full height. Missing, invalid or previously Collapsed (`PanelDisplay = 2`) values restore Full for older definitions.

The managed test runner uses deterministic yield policies to check resumable scans, empty branches, sorting, cancellation and worker handoff without timing-sensitive assertions. It also covers query behavior and pure canvas menu/size logic without Rhino. The separate Windows Rhino smoke harness checks budgeted query publication, expired-input loading states, cancellation, downstream filtered output (including asynchronous geometry completion), host integration, tree transformations and combinations, upstream preservation, saved settings, legacy defaults, output recomputation, and native UI interactions. Its test adapter contains the reflection needed to inspect the loaded `.gha` and host-owned controls. The review image in `docs/images/panel-tree-tools.png` comes from the actual native Objects renderer with a solved sample tree and illustrative grid/wires. Tree-tool glyphs are vectors drawn in canvas units with the panel's muted and accent colors; their drawing state is restored after each icon. Footer text and controls share a vertical center, and statistics use the same font as status text with a compact gap.

Packaging builds `net48` and `net7.0`, derives manifest versions from `Directory.Build.props`, and stages only the expected runtime payloads. `npm run check` runs behavior, packaging, build/staging, and focused unused-code checks locally on Windows or Mac; it does not launch Rhino. GitHub Actions CI is disabled. The archived browser study in `prototype/` is a visual reference with an independent sample-data engine, including its own histogram and paging UI. `docs/architecture.md` preserves the original proposal.
