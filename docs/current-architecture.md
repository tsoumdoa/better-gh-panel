# Current architecture

`BetterPanelComponent` applies saved tree tools in order: Simplify, Trim, Flatten, Reverse. With tree tools and unit conversion off, it forwards Grasshopper's typed input tree unchanged. `PanelTreeOperations` copies paths and branch lists before changing structure, preserving typed goo and upstream data. Simplify removes shared path indices before Trim removes trailing path indices, merging coincident branches in source order; fully trimmed paths become `{0}`. The component captures a presentation snapshot of the output once per solution. `SnapshotCapture` caches primitive summaries and keeps live goo references in the component for full-value copying on the Rhino UI thread.

`BetterGhPanel.Core` owns immutable snapshots, query options, stable source positions, filtering, cancellable sorting, and scalar statistics. Query `RowPositions` indexes `Snapshot.Rows`; each row retains its path and original index within that branch. The canvas reads visible rows directly through these positions. Snapshots use object identity for ownership checks, without separate version or row/branch identity fields. Matching branch paths are collected only to calculate the branch count, including empty branches when browsing without item filters.

`GeometryHints` captures analytic primitive measurements and stored properties as immutable `PanelGeometryInfo` records with raw values, dimensions and model units. Painting submits visible row positions to `PanelSession`; it never duplicates or measures geometry inline. After a 40 ms delay, a UI callback prepares a deep curve/Brep copy and one background operation computes general curve length/linearity, trimmed surface/open Brep area or solid Brep volume. The worker owns and disposes its copy and never accesses source goo or the Rhino document. Pending rows show measuring status; successful and failed results are cached by source position and repaint the panel without another query or solution. Each session runs at most one geometry operation. Only row bounds intersecting the canvas viewport enter the pending queue. Scrolling and canvas panning replace that queue; offscreen panels and zooming below the row display threshold clear it. Canvas clipping does not change table layout or scroll capacity. Queued rows that leave view are skipped. A native mass-property call already running cannot be interrupted; it finishes and releases its copy, with stale publication rejected.

A normal new solution invalidates geometry cache entries; a unit-only solution retains completed and pending entries only when source goo identity, position and model units still match. Entry identity rejects stale callbacks across new solutions and disposal. Invalid, obsolete and disposed views cannot start geometry work. `PanelUnits.FormatGeometry` applies only conversions matching the model units and metric dimension, with decimal changes formatting cached raw values. Geometry output is never scaled. Invalid rows carry a captured validity reason and visible text label. Full-value copying and background filtering retain their existing behavior; asynchronous metrics do not enter text search. No live geometry enters the managed snapshot. McNeel's [asynchronous execution guidance](https://developer.rhino3d.com/guides/scripting/advanced-async/) describes the separation between background work and document/UI access.

`PanelGeometryInfo` separates its compact description from labeled tooltip details. The same summary builders capture pending metadata and construct measured results, so a metric augments the original trimming, degree, topology and count information. Curve linearity/planarity and single-face surface planarity are computed on the owned background copy. Rows keep the type, a few relevant properties and the metric; geometry rows do not repeat a separate type label. Tooltips show the formatted metric once, followed by labeled properties, including surface U/V degree and Brep face/edge/vertex counts. Pending and failed rows retain the available metadata, and unit/decimal changes reformat the metric without removing those details. Planarity uses RhinoCommon's default zero tolerance.

`PanelUnitOperations` converts Number and Integer values after tree tools using `PanelUnits` in the core. It copies paths and branch lists, creates full-precision Number goo, and preserves other items and empty branches. Modes distinguish length (mm ↔ m), area (mm² ↔ m²), volume (mm³ ↔ m³), and angle (rad ↔ deg). A footer dropdown opens upward and also exposes automatic or 0–12 decimal places. Decimal changes invalidate the canvas without recomputing the solution; rows, numeric copying, and statistics share formatting. Snapshots carry their conversion mode so obsolete results retain the correct unit suffix while a newer query completes. Saved conversion and decimals default to off/automatic for older definitions and participate in undo. Query filters operate on the converted snapshot numbers; output precision is never changed by formatting.

One `PanelSession` per component owns the current snapshot, copied options, and the published result. Queries run against managed snapshots in the background. Cancellation and request numbers reject obsolete results before UI publication. Changed options mark the document modified through `QueryChanged`; query progress and completion invalidate the canvas directly. Equal options do not trigger another scan. The component's reset path explicitly closes draft editors and clears transient canvas state, even when the query options are already at their defaults.

`BetterPanelAttributes` draws the canvas and handles tree tools, row interaction, scrolling, inline editing, and resizing. Tree tools expire the solution, record undo, clear branch selections when paths can change, and mark the definition modified. Search, filters and sorting affect only the view. The header Reset and Reset panel menu command restore all data settings in one undo step and recompute the original input when output tools were active. Reset also clears transient selection and scroll, closes dropdowns before menu hit handling, and cancels the component's owned text editor. Reset panel view and Reset tree tools remain separate context-menu commands. `CanvasMenu` owns compact dropdown layout, selection, hover and paging; its navigation row never overlaps selectable items. `CanvasPanelSize` owns dimension validation and presets. Selection and full-value lookup use snapshot positions with ownership checks. The modeless inspector and its row view were removed in `0.1.3-beta.1`.

Width and height are canonical saved settings. New panels use 360 × 360; existing dimensions and size presets retain their original behavior. Preset check marks are derived from dimensions. Serialization retains the legacy `PanelSize` key, and reads it as a fallback when dimensions are absent. Missing tree tool settings default to disabled, preserving older definitions' output. Document closure releases sessions; a tab switch closes the editor and clears queued geometry requests while retaining the snapshot and cache. A geometry operation already running can finish, but more work only starts after the panel becomes visible again.

`CanvasPanelDisplay` is a separate saved presentation setting: Full uses the canonical height and Half derives half that height. One header chevron toggles Full ↔ Half. Display changes record undo and invalidate layout without solving or changing query options. Wire grips use the canonical full-size coordinates in both modes; the visible body uses a derived top offset. Resizing in Half maps the visible height back to the canonical full height. Missing, invalid or previously Collapsed (`PanelDisplay = 2`) values restore Full for older definitions.

The managed test runner covers query behavior and pure canvas menu/size logic without Rhino. The separate Windows Rhino smoke harness checks host integration, tree transformations and combinations, upstream preservation, saved settings, legacy defaults, output recomputation, and native UI interactions. Its test adapter contains the reflection needed to inspect the loaded `.gha` and host-owned controls. The review image in `docs/images/panel-tree-tools.png` comes from the actual native Objects renderer with a solved sample tree and illustrative grid/wires.

Packaging builds `net48` and `net7.0`, derives manifest versions from `Directory.Build.props`, and stages only the expected runtime payloads. `npm run check` runs behavior, packaging, build/staging, and focused unused-code checks locally on Windows or Mac; it does not launch Rhino. GitHub Actions CI is disabled. The archived browser study in `prototype/` is a visual reference with an independent sample-data engine, including its own histogram and paging UI. `docs/architecture.md` preserves the original proposal.
