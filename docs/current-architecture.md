# Current architecture

The property inspection added in `0.1.25-beta` uses immutable `PanelPropertyValue` records on captured rows and geometry summaries. `PanelProperties` owns property kinds, labels and lookup; input snapshots union property keys once for menu capabilities. Null entries advertise deferred properties. Exact stock holders are read by `PanelPropertyCapture`; general geometry shape/planarity is completed on owned worker copies. `PanelPropertyFilter` compares typed numeric, Boolean, text and calendar-time values without parsing tooltip prose. Display, value copy, displayed sets and property sorting share that representation. Existing search-mode enum values remain unchanged, and new modes are appended. `StockGooSupport` is the runtime catalog of compile-checked exact holder types, names and independent validity, managed capture, native capture, preview, measurement, shape-only load and group-reference validity facets. Native entries own their typed value reader and exact inner types. `StockTypeLabels` is a plain name-to-label/separate-label table shared by the runtime and pure UI tests. Typed property readers and managed copy/equality remain explicit; Core and its pure menu tests do not load Rhino.

Text Dot uses the existing owned preview/copy pipeline and displays its text. Dots and annotation/hatch origins use `PanelComponents` for X/Y/Z. Dimensions use unit-aware length/angle metrics; angles follow the existing radians-to-degrees property convention. Dot font size is screen pixels; annotation text height is omitted because stock value getters strip the dimension style. Create set groups dots by displayed text. Native text capture rejects strings beyond the preview text limit; admitted text uses the existing bounded canvas/tooltip presentation.

Annotation/hatch/block/detail inspection concerns the captured native shape, not separate styles, patterns or definitions; those dependencies are not traversed or previewed/copied. Referenced shapes still require document/object context. Culture witnesses freeze name/English name strings; Matrix witnesses retain at most 4,096 managed cells and paths at most 4,096 indices, charging those sizes to the capture-wide 100,000 visit budget before retaining the witness. Graph rechecks count the same sizes. Numeric summaries retain bounded managed values and use the active precision for display, text filters, copies and set equality. Matrices and transforms share one summary formatter. Material/Field rows do not inspect assets/elements and remain unverified.

Picking a comparison mode shows its values with `DisplayFilterValue` and an empty search expression; clicking the search field opens the optional filter picker. Core filtering bypasses the comparison while retaining branch/type/invalid restrictions. `PanelFilterValue` shares metric eligibility, circle circumference and presented-number rounding with comparisons; the canvas and metric copying use its formatter. Geometry display retains the visible-row measurement queue. `BetterPanelAttributes.FilterValues` renders list lengths once per matching branch, including empty branches, using transformed snapshot counts. Scroll and jump addresses refer to branch rows in that view. D/S choose Items or Values independently of the value display. Values without a set are frozen typed property records at presented precision in displayed units; unavailable values retain a null slot. Values output queries prepare offscreen measurements before publication. Plain value display keeps visible-row measurement and does not wait for offscreen rows. Statistics skip unmeasured values and use available presented numbers, including displayed metrics and properties; Numeric unique values group by numeric keys equivalent to presented text; Automatic keys use fast significant-digit rounding with exact midpoint fallback, and unique text is formatted lazily. Automatic unique rows use the shared row formatter; their tooltip retains round-trip precision. Legacy archives default to the ordinary item view. The native host inventory focuses on geometry capture, resource ownership, drawing and clipboard integrity; routine filter and UI smoke fixtures have been removed.

The [maintainability audit and feature guide](maintainability.md) maps extension points and remaining considerations. `PanelUnits` owns conversion definitions in one catalog; `PanelQueryScope` shares cheap restrictions between final queries and geometry preparation; named row actions keep menu presentation and dispatch aligned in the row-action feature partial.

`PanelOrderLabels` maps ordinary rows to their zero-based `OriginalIndex` after tree tools, and all members of a set to its stable set index k. Filtering, sorting and selection do not renumber labels. Repeated indices across branches and coincident anchors are valid; the existing selected-first collision handling decides visibility. Label caches are still discarded for obsolete results and inactive preview scopes. With item order enabled, row tooltips show the matching branch path and index.

The footer's **Select all** button uses `PanelRowSelection.SelectAll` over the current query result, including offscreen rows. It shares row-action currency guards, pending-copy cancellation, highlighting and selection cleanup. Full and minimum Half layouts reserve space beside Stats, and capsule layout clears the control's hit target. Repeated clicks preserve the full selection; selection leaves D unchanged, updates S and the Selection B/F scope, and never frames the camera.

The padded header move target delegates mouse-down to Grasshopper so native dragging, selection and undo stay intact. Move/resize hover consumes the event after setting its cursor, preventing the host from replacing it. The resize target is 24 × 24 canvas units; the footer ends 28 units before the right edge to keep controls separate. Native host checks exercise header dragging and every padded corner in Full and Half layouts.

`CanvasRowRenderer` draws the numbering gutter and aligns row text by font ascent against one canvas-unit baseline. Asc/Desc sorts within each branch, retaining snapshot branch order, and shows the one-based index into the complete current result beside the original branch item index in a smaller bracketed slot. These global view numbers remain the target for Jump to row. Source order uses a compact gutter for the original item index alone. Both source and sorted rows use branch headings and omit the inline path column when there is room; panels too short for headings retain inline paths. Gutter capacity uses the full snapshot item count, which bounds every captured branch index, so paint never scans the tree or resizes columns based on filtered or scrolled rows. Numbering is transient presentation, adds no saved setting, and does not change selection identity, query order or typed output. Row hits retain the view number for tooltip lookup without searching the result. Numeric cells use right-aligned monospaced text; other data retains left alignment. Row height stays 17 canvas units. The native host checks cover digit-boundary filtering, row jumps beyond the viewport, selection retention, output invariance and the minimum Half layout.

Row selection is bound to a snapshot and uses source positions, with ranges and copy order taken from the current query result. Replacement-input solutions cancel live query previews, then explicitly re-bind committed selection by source position only when paths and branch lengths match and Create set is off; structural changes and Create set recomputes clear it. Output-only solutions preserve it. Filtering removes hidden selections and sorting retains matching source positions. Actions reject obsolete snapshots, pending queries and stale row hit regions. Row and branch-heading clicks select without moving the camera. Double-clicking a row or branch heading clears selection. Double-clicking empty table space does not open search. Panel header clicks retain Grasshopper's component dragging behavior. Blank-canvas and empty-panel clicks retain selection. A canvas observer handles document switches and disposal, clearing selection and borrowed previews. Branch filters clear selection and only narrow the query. The explicit Frame selection context-menu action only moves the camera, using the same bounds resolver as preview, including custom preview goo. Clearing row selection also cancels pending copying and closes its action menu while retaining the Results preview scope. Right-click actions retain an existing multi-row selection; value and geometry copying remain explicit context-menu actions.

`PanelGeometryHighlight` participates in the component's native Grasshopper preview callbacks. It borrows preview goo only for the current scope: selected positions in Selection mode, or every query match in Results mode; sets expand representatives to all member positions in either scope. Off clears the preview cache. No callback falls back to the base component's full-tree preview. Selected rows use Grasshopper's selected wire/material settings; other matches use normal colors even when the component itself is selected. Clipping bounds cover only the drawn scope and are empty when preview is off, hidden, locked or suspended. Selected wires receive Grasshopper's small clip-depth bias and configured thickening when the component has not already received them from the native selection pass; the drawing transform is restored afterward. This keeps upstream previews from covering the highlight without changing geometry or disabling depth testing. Other components' previews remain independent.

The header preview menu stays available in Full and Half layouts. `PanelPreviewMode` is saved as `PanelPreviewMode`, defaults to Selected for missing or unknown values, and records undo without expiring the solution. Reset all retains the mode while clearing selection and filters. Query start, new solutions, saved-state reads, and document unload/removal clear borrowed previews. Query publication synchronizes selection and rebuilds the scope independently of painting, including offscreen matches; empty and failed queries draw nothing. Document switches clear selection, and reactivation restores the current Results scope when appropriate. Repainting, sorting, filtering, selecting and switching preview modes never frame the camera. No preview operation bakes geometry or changes Rhino object selection.

`PanelQueryOptions.SearchMode` selects Text, Regex, Value, Length, Area, Volume or ListLength while `Search` holds the text, pattern or comparison. The search dropdown reuses the existing compact canvas menu and inline editor. Text retains legacy numeric comparisons; comparison modes support greater/less comparisons, equality and inequality. Text and regex use `PanelValuePresentation` for the same converted, decimal-formatted value shown on the canvas, including completed geometry measurements and stable measurement failures; Text also searches paths and types. Regex uses case-insensitive, culture-invariant matching and time limits. Whitespace in regex patterns remains significant in both query execution and output-filter detection. ListLength compares each transformed branch's count before type or invalid-only item filters; matching empty branches survive when no item filter excludes them. Branch input accepts `0;0;1` or `{0;0;1}`, canonicalizes valid paths and reports malformed paths as query errors. Invalid expressions publish an error and disable stale row actions. Modes persist with the definition, default to Text for older files, and reset with the view.

Geometry filtering first validates the query and collects eligible branch/type/valid primary-metric candidates on a worker. Displayed-text queries and nonnumeric value sorting also collect eligible measurements, including offscreen rows, before publishing their complete result. The session measures those positions through its existing single geometry worker, then captures an immutable measurement map on the UI thread for the final managed query. Scalar comparisons exclude geometry from that work. The query retains the original snapshot identity and source positions; cancellation and request ownership reject obsolete results. Metrics compare presented display-unit values using the same source-unit/dimension conversion guards as formatting. Length covers curves and circle circumference; area covers rectangles, surfaces and open Breps; volume covers boxes and closed Breps. Unsupported secondary metrics are excluded. Visible-row measurement and copying share the same cache and queue.

Value copying follows the current result order, including sorting within branches. It uses converted snapshot numbers or the geometry metric with matching unit/dimension conversion, without unit labels and with a decimal point for pasting. Unit conversion, factor rounding, then explicit decimal rounding produce one number for display, copying, comparisons, statistics and typed output. Automatic uses compact G12 scalar / G6 geometry formatting without decimal rounding on the wire; Automatic Create set retains compact displayed grouping and Values. Explicit decimals use a faithful 15-significant-digit decimal cast, otherwise the exact binary rational (mantissa times a power of two), rounded half away from zero without a factor, or toward positive infinity with a factor. The factor step retains the original guarded decimal/binary ceiling; explicit decimal ceiling reconstructs a faithful factor’s nearest intended multiple with exact binary/decimal rational division and guarded decimal arithmetic, otherwise using the exact binary rational. Reconstructed input grid points remain stable on re-application. When the base guard retains a nongrid input with commensurate settings, explicit precision emits the next factor grid point to avoid intermediate decimal points that drift. Thus 2.675 at 2 dp becomes 2.68, as in Excel. Values at or above 2^53 retain their exact integer digits. Decimal formatting is invariant; no double formatting/parsing selects the presented value. Decimal-to-double conversion starts with the cast and corrects its occasional scale-dependent last-bit error with exact rational arithmetic; the decimal operand parser shares this conversion. Outside decimal range, operands use an exact integer-rational parser. Both runtimes run the same seeded 100,000-value, 0–12 dp text/bit fingerprint and independent arithmetic oracle in Core.Tests. Sets retain typed explicit presented numbers. Explicit measurement batches share the session's single background worker with visible-row measurement, allowing offscreen selected rows to complete. Cancellation, new snapshots and session disposal resolve pending requests and prevent stale clipboard writes. Formatting and clipboard publication execute on Rhino's UI thread. Text rows retain their full content despite canvas clipping; other rows without a supported scalar metric use the shared displayed summary, including invalid markers and point/vector coordinates. Unavailable measurements fail the whole value copy without replacing the clipboard.

Geometry copying duplicates supported geometry into a private 3DM archive with the source solution's model units and tolerance, then publishes the native Windows Rhino clipboard format. No objects are baked into or deleted from the user's Rhino document. Unsupported, invalid and non-geometric rows are skipped and reported. An empty supported selection leaves the clipboard untouched. Native Mac geometry clipboard and custom model units remain unsupported.

`BetterPanelComponent` applies structural tree tools in order: Simplify, Trim, Flatten, Reverse. Unit conversion follows, then the query filters rows and Create set groups the resulting displayed values. With all operations and filters off, it forwards Grasshopper's typed input tree unchanged, including negative zero. Original and presented scalar witnesses are captured once per solve and reused for tree conversion and currency checks; freshness still compares the live original bits. A transformed overflow is unavailable, not invalid or null in source diagnostics; typed output retains a null slot. `PanelTreeOperations` copies paths and branch lists before changing structure, preserving typed goo and upstream data. Simplify removes shared path indices before Trim removes trailing path indices, merging coincident branches in source order; fully trimmed paths become `{0}`. `PanelDisplaySet` groups full formatted strings per branch after filters, with original input addresses carried by `PanelSnapshot.SourceAddressAt`. Its immutable result stores displayed values, stable per-branch set indices, original occurrence locations and transformed member positions, accumulated in the cooperative tree-order query. `PanelOutputOperations.DisplaySet` emits unique frozen values; `SetItems` groups D/S members in `{path;k}` (flattened `{k}`). `PanelPairedData.Output` uses those same groups for F in both modes. List-length sets use `{k;path}` for member branches, including empty branches. B and geometry actions expand all members. Set row/order labels use k, independently of view sorting. The saved `PanelOutputValues` enum defaults to Items; missing keys on old sets migrate to Values. Selection explicitly tracks empty branch paths. Set statistics describe emitted values, and sorting uses their numeric/text keys without changing wire order. Geometry needed by set equality completes through the query measurement batch, including offscreen rows. The component owns a structural copy of the transformed tree and captures a presentation snapshot before filtering. Without Create set, query row positions select typed goo from that same captured tree; matching branch paths preserve empty branches when no item filter is active. Output keeps transformed tree order independently of view sorting. A pending or failed filter or set query outputs an empty tree. Query changes and completion schedule a normal Grasshopper solution to update downstream objects. An internal publication solve reuses the captured tree and query, avoiding repeated geometry calculation. Normal upstream expiration clears that reuse flag, cancels obsolete work and invalidates the UI before replacement input arrives. Snapshot identity, document ownership and request numbers guard scheduled output callbacks. `SnapshotCapture` caches immutable summaries; the component retains current live goo for typed output, geometry actions and UI-thread measurement preparation.

`BetterGhPanel.Core` owns immutable snapshots, query options, stable source positions, filtering, cancellable sorting, and scalar statistics. Query `RowPositions` indexes `Snapshot.Rows`; each row retains its path and original index within that branch. Value sorting groups matches in snapshot branch order and stably sorts each branch independently. Numeric comparisons use the presented number; nonnumeric comparisons use cached shared presentation text. The canvas, range selection and copying all consume that same result order. Snapshots use object identity for ownership checks, without separate version or row/branch identity fields. The result also carries matching branch paths, including empty branches when browsing without item filters, for both statistics and typed output filtering. Invalid finite numbers are excluded from numeric filtering and statistics along with null, NaN and infinite values.

`GeometryHints` captures analytic primitive measurements and stored properties as immutable `PanelGeometryInfo` records with raw values, dimensions and model units. Painting submits visible row positions to `PanelSession`; it never duplicates or measures geometry inline. After an initial 40 ms scrolling delay, a UI callback reconstructs a bounded curve from values or duplicates a standalone curve/Brep using the compatibility fallback, and one background operation computes general curve length/linearity, trimmed surface/open Brep area or solid Brep volume. The worker owns and disposes its copy and never accesses source goo or the Rhino document. Fallback duplication may invoke installed UserData callbacks, and its native work and allocation are unbounded; see [geometry measurement integration](geometry-measurement-safety.md). Pending rows show measuring status; automatic viewport measurements cache successful and failed results by source position and repaint the panel without another query or solution. The queue continues without another scrolling delay for each row, while measurement redraws are coalesced over 60 ms. Each session runs at most one geometry operation. Only row bounds intersecting the canvas viewport enter the automatic pending queue; explicit query and copy batches can request offscreen rows. Scrolling and canvas panning replace the viewport queue; offscreen panels and zooming below the row display threshold clear it. Canvas clipping does not change table layout or scroll capacity. Queued viewport rows that leave view are skipped. A native mass-property call already running cannot be interrupted; it finishes and releases its copy, with stale publication rejected.

A normal new solution invalidates geometry cache entries; a unit-only solution retains an entry only when a complete new witness matches the copied geometry and context. Compatibility results have no witness and are remeasured on a new snapshot, while output-only solutions preserve the same snapshot's cache. Entry identity and captured source checks reject stale callbacks across new solutions and disposal. Invalid, obsolete and disposed views cannot start geometry work. `PanelUnits.FormatGeometry` applies only conversions matching the model units and metric dimension, with explicit decimals rounding the presented number from cached raw values. Geometry output is never scaled. Invalid rows carry a captured validity reason and visible text label. Completed asynchronous metrics and stable measurement-unavailable labels enter text/regex matching through the shared presentation formatter. No live geometry enters the managed snapshot. McNeel's [asynchronous execution guidance](https://developer.rhino3d.com/guides/scripting/advanced-async/) describes the separation between background work and document/UI access.

`PanelGeometryInfo` separates its compact description from labeled tooltip details. The same summary builders capture pending metadata and construct measured results, so a metric augments the original trimming, degree, topology and count information. Curve linearity/planarity and single-face surface planarity are computed on the owned background copy. Rows keep the type, a few relevant properties and the metric; geometry rows do not repeat a separate type label. Tooltips show the formatted metric once, followed by labeled properties, including surface U/V degree and Brep face/edge/vertex counts. Pending and failed rows retain the available metadata, and unit/decimal changes reformat the metric without removing those details. Planarity uses RhinoCommon's default zero tolerance.

`PanelUnitOperations` converts valid Number and Integer values after tree tools using `PanelUnits` in the core. It copies paths and branch lists, creates Number goo at presented precision (preserving Integer goo when only decimals are set), and preserves invalid numeric goo, other items and empty branches. This prevents scaling Rhino's finite unset sentinel into a valid number. Modes distinguish length (mm ↔ m), area (mm² ↔ m²), volume (mm³ ↔ m³), and angle (rad ↔ deg). A footer dropdown opens upward and also exposes automatic or 0–12 decimal places. Decimal changes recapture numeric items and refresh the query and canvas; when an active text/regex filter uses displayed text, changed membership also updates downstream output. Create set also requires output recomputation when decimals change. Explicit decimal changes recompute numeric wire output. Rows, numeric copying, filtering and statistics share formatting. Snapshots carry their conversion mode so formatting and filtering use the same units. Obsolete results are hidden while a newer query completes. Saved conversion and decimals default to off/automatic for older definitions and participate in undo. Numeric comparisons use presented numbers, with explicit decimals shared by display and wire output; Automatic retains full precision except for compact displayed Create set Values.

One `PanelSession` per component owns the current snapshot, copied options, and the published result. `PanelQueryWork` gives managed queries a 120 ms UI time budget measured with a monotonic stopwatch, independent of row and branch count. Checkpoints cover empty-branch scanning, each row, branch grouping, sorting and result construction. When the budget expires, the same iterator continues on a worker with its scan position, statistics and merge-sort state intact; no partial result is published and no scan is restarted. Worker completion bypasses deadline checks and iterator handoffs inside the loops. The deadline is cooperative: individual string operations, allocations and copies can overrun it. Regex and queries requiring native geometry measurements start in the background because a single operation cannot yield midway. `HasCurrentResult` gates rows, hit regions, counts, type summaries, statistics and tooltips. Pending views show Recomputing… with an animated spinner; the session owns its timer, runs it only for a visible busy panel, and stops it on completion or disposal. Disabled components invalidate their input into an idle suspended state, cancel pending work and stop animation. Their canvas shows Disabled until re-enabling supplies a new snapshot; query edits and late worker completions cannot restart them. Errors hide stale results too. Cancellation and request numbers reject obsolete results before UI publication. Changed options mark the document modified through `QueryChanged`; query progress and completion invalidate the canvas directly. Equal options do not trigger another scan. The component's reset path explicitly closes draft editors and clears transient canvas state, even when the query options are already at their defaults.

`BetterPanelAttributes` draws the canvas and handles tree tools, row interaction, scrolling, inline editing, and resizing. Tree tools expire the solution, record undo, clear branch selections when paths can change, and mark the definition modified. Search and filters also change typed output; sorting changes view/copy order within branches, and explicit decimal rounding changes numeric wire values and may also change text/regex membership. The header Reset all and Reset all menu command restore all data settings in one undo step and recompute the original input when output tools were active. Reset also clears transient selection and scroll, closes dropdowns before menu hit handling, and cancels the component's owned text editor. Clear filters clears query settings, sorting, selection and scroll in one undo step. Reset all additionally resets tree tools, units, rounding, decimals, Out Items/Values and B + F follow, keeping Preview mode, item order, D|F split and size. `CanvasMenu` owns compact dropdown layout, selection, hover and paging; its navigation row never overlaps selectable items. Closing a menu releases its captured snapshot, type choices and statistics result; handlers capture a selected path or type before closing. Input expiration, disabling and document closure also release painted-result and borrowed-source references so stale trees are not retained until another render. `CanvasPanelSize` owns dimension validation and presets. Selection and value lookup use snapshot positions with ownership checks. The modeless inspector and its row view were removed in `0.1.3-beta.1`.

Width and height are canonical saved settings. New panels use 360 × 360; existing dimensions and size presets retain their original behavior. Preset check marks are derived from dimensions. Serialization retains the legacy `PanelSize` key, and reads it as a fallback when dimensions are absent. Missing tree tool settings default to disabled, preserving older definitions' output. Document closure releases sessions; a tab switch closes the editor and clears automatic viewport measurement requests while retaining the snapshot and cache. An operation already running can finish. Automatic measurement resumes when the panel becomes visible; explicit filter batches may continue in the background, with viewport highlighting and camera framing suspended for the inactive document.

## D/F branch pairing

`PanelPairing.Match` reserves every exact original path before pairing remaining branches in tree order. Only original branch-count differences block pairing. `PanelPairedData` holds that map, the transformed D-position → optional raw F-position lookup, original branch lengths, and original-branch destination paths. A branch marker tree carries empty branch identities through the same structural tools as D. The raw F snapshot includes every F item, including extras, so its existing capture/freshness fences cover all published and displayed values.

The positional-assumption audit is resolved at these boundaries:

| Previous assumption | Current behavior |
| --- | --- |
| `PanelOutputOperations.Pair` constructs a D-shaped F tree | Constructs the explicit identity map; no placeholder goo or fabricated F rows. |
| F snapshot capture / `CanSplit` use D-shaped positions | Capture the original raw F tree; availability requires a valid map and current D result. |
| Renderer indexes `PairedSnapshot.Rows[D position]` | `PairedRow` resolves an optional F position. A shared display index adds F extras and blank D spacers; extras have no row hits. |
| Tooltips / full-value window use D positions in F | Resolve the same optional F row/value; missing F cells have an empty value. |
| Caption / branch summaries assume D counts | Report original differing lengths and fallback pairing; headings use F counts and original D count badges. Branch-level summaries enumerate mapped F items, including empty-D partners. |
| RevealPartner / keyboard / jump / scrolling use only D view offsets | Translate through the augmented display index. Selection and navigation still address D rows and skip extras. |
| `CopyPairedValuesAsync` reads F at D positions | Copies mapped raw F values, with an empty line for a missing F item. |
| `PanelTreeOperations.Filter` / `Select` can filter F by D positions | Used only for D/S. F output uses original branch scope and destination identities. |
| `SetItems` on F can use D member indices | F visits the same stable set groups: equal original lengths select individual members; unequal lengths emit the whole F branch once per group. |
| F port publication can reuse a D-shaped filtered tree | Caches the mapped F output per query and rebuilds only selected scope; the existing final capture fence covers publication. B remains D's original-shape mask. |

When filters hide a paired item in an unequal branch, that retained F value appears as a muted nonselectable row labelled "paired with hidden D rows". Only indices beyond the original D branch length are "only in F". Both follow F output order, including Reverse. Reverse reverses the paired prefix with D; additional F items remain after D's rows. Sorting remains a presentation operation. When structural tools merge branches, F-only tails follow the merged D rows in original branch order. Unequal F branches are duplicated into every set Items group containing a member of their original D branch. Every item or list-length set uses one bounded F summary cell in emitted order, with a remaining-value count and no hidden/F-only notes. Filtered output builds four preview positions and the total per group, so painting never expands set members. Copying a set cell traverses the full emitted group. List-length sets retain `{k;path}`; empty D partners are excluded whenever either kind of Create set is active.

The native `branch-pairing` fixture verifies actual D/S/B/F publications, identical F/set-Items paths in both output modes, source identity through tree tools, empty branches, copy/navigation behavior, and native canvas captures of uneven, order-paired and mismatch states. The isolated `pairing-wysiwyg` fixture checks pane-specific heading copies, raw F addresses and TSV after Reverse, nonselectable extras and hidden partners, clipped hover glyphs, and warning/caption spacing in Full and Half, with light/dark captures.

Paired display indices cache item offsets and the next D item for spacer runs per result/map identity. Original branch scope comes from expanded current query members. The query engine's shared item-filter predicate admits empty D partners without item filters and without Create set; path and list-length restrictions retain them whenever D retains the destination; admitted partners follow their destination even when merged with nonempty branches. Output, pane rows, summaries and heading counts share that rule. Branch summaries use current item matches for equal pairs and whole-branch expansion for scoped unequal pairs, retaining four preview positions. Named heading summaries cache counts with and without empty partners. Integer pair indices resolve original positions directly; equal-length trees and all sets use `ViewIndex` without augmented row allocations. Every F item gutter and tooltip uses the raw F original index with the same sorting flag. F headings use scoped partners for all metadata and show emitted versus total counts under item filters.

The `stock-types` inactive-desktop fixture checks native type inspection, WYSIWYG property output and owned Text Dot actions.
