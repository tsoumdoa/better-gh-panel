# Extension points and known considerations

- Pure filtering, sorting, statistics and presentation policy belong in `BetterGhPanel.Core`. Its tests run without Rhino.
- Typed tree changes belong in `Runtime/PanelTreeOperations` or `PanelUnitOperations`; snapshots remain immutable managed records.
- Geometry preparation, measurement ownership and publication go through `PanelSession`. Workers must not read live goo or the Rhino document.
- Canvas policy belongs in `BetterGhPanel.Core/` and `UI/`; Rhino event dispatch and drawing stay in `BetterPanelAttributes` and its feature partials. The core test project references Core and links drawing policy explicitly.
- Saved settings, output publication and host lifetime belong to `BetterPanelComponent`. Removing a feature must account for older saved enum values and serialization keys before deleting them.
- Split view saves `PanelSplit` on `BetterPanelComponent`, derives twice the canonical width, and uses a presentation-only Undo action; Reset retains it. `BetterPanelAttributes.SplitView` owns pane rectangles, transient scroll locking/F offset and captions, while both panes share the row painter, hit lists and `BetterGhPanel.Core.PanelRowSelection`.
- `PanelPairing` diagnoses original branch counts and reserves exact-path matches before order fallback. `PanelPairedData` maps original identities through D's tools and resolves optional F items, whole unequal branches and extras; see the [pairing rules](architecture.md#outputs). The component captures a raw F presentation snapshot only for split view; canvas code never inspects live F goo or applies D's units to it.
- `BetterPanelComponent.Outputs` owns the saved B/F scope, paired input cache and publication of D/S/B/F from one current snapshot. The saved Items/Values mode controls D/S independently of B/F scope. Set membership records transformed positions and stable k indices once in Core; outputs and geometry actions expand those same groups. Component-owned `BetterGhPanel.Core.PanelRowSelection` notifies output scheduling; selection-only solutions reuse the snapshot and cached filtered trees. `PanelTreeOperations.ApplyWithSources` carries retained original addresses through every tree tool; filtering and selection share its tree-order traversal while retaining their different empty-branch behavior. `PanelOutputOperations` builds original-shape masks and paired trees without converting paired values. Match paths with `GH_Path.CompareTo`, since object equality does not compare their indices.
- Filtered D/B/F trees are cached per completed query result so selection gestures do not rebuild unchanged filters or masks. Selection notifications describe membership changes; preserving the same group or changing only the range anchor does not schedule output. Empty selections skip tree scans, and masks allocate one Boolean value per input item.
- `BetterPanelComponent.Settings` upgrades only the known unversioned one-input/one-output archive before the host reads its parameters. It preserves D chunks/GUIDs and the original archive owner for relative paths and diagnostics, supplies defaults for the added ports, and leaves the source archive unchanged. New saves carry `PanelOutputSchema`; genuine missing chunks still report errors.
- Native wire picking uses a 12-unit radius and reverse parameter order, beyond the custom rectangle bounds. Port spacing must keep neighbouring grips outside that radius at each target edge and leave the Half resize corner clear. Presentation controls, rows, scroll tracks and menus stay at least 14 units inside the relevant side. The 96-high capsule gives its four outputs 24-unit spacing.

- `BetterGhPanel.Core.PanelQueryPolicy` keeps query equality, downstream output equivalence and active-filter decisions separate. Output equivalence ignores sorting, but includes explicit decimal precision and factor rounding because they affect presented values and numeric Items.
- `BetterGhPanel.Core.GeometryMeasurementQueue` owns prepared work, cancellation and worker handoff; `PanelSession` retains query state and publication. New measurement providers must preserve UI dispatch, copy ownership, context checks and safe retention across unit changes.
- Host fixtures now use the production preparation seam; the unused HostMeasurementPreparation helper has been removed. The real compatibility admission limit and queue ownership checks remain in production.
- Selection gestures repeat cancellation, highlighting and repaint side effects. Consolidate only after distinguishing gesture updates from query-completion synchronization and document changes.
- The archived HTML prototype is documented as a visual reference and has an independent data engine. Removing it is a product/documentation decision, not dead-code cleanup in the native plugin.
