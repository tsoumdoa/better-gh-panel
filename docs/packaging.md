# Build and Yak packaging

BetterGhPanel follows HopperWire's Rhino 8 package layout and AECTooling metadata. The package contains `net48/` for Rhino's .NET Framework mode on Windows and `net7.0/` for Rhino's .NET mode on Windows and Mac. The pure data engine targets `netstandard2.0` and is shipped beside each `.gha`. Rhino supplies Grasshopper, RhinoCommon, Eto, System.Drawing, and WinForms; those SDK assemblies are compile references and are not copied into the package.

Run these commands from the repository root:

```text
dotnet build BetterGhPanel.sln -c Release
dotnet test BetterGhPanel.sln -c Release
node scripts/package.mjs
```

Packaging finds Yak in the standard Rhino 8 installation. On a machine without Rhino, `node scripts/package.mjs --stage-only` builds the same folder without creating an archive. Use `--yak <absolute path>` or `YAK_PATH` for a custom installation. Use `--skip-build` only after a successful Release build.

`Directory.Build.props` maps the checkout root to `/_/` in debug records, keeping local usernames and checkout paths out of newly built assemblies and PDBs. Rebuild before packaging. On 2026-10-24, all 25 existing GitHub release downloads were refreshed to remove local paths from CodeView records; their executable code and versions are unchanged, and published checksums were updated.

McNeel's separate public Yak registry still serves the original packages. Published registry versions cannot be overwritten; yanking hides them from searches but retains direct installation. Removing those stored copies requires McNeel support. See the [public-repository cleanup notes](maintainability.md#public-repository-cleanup).

The current published beta is [`0.1.23-beta`](https://github.com/tsoumdoa/better-gh-panel/releases/tag/v0.1.23-beta), a maintenance patch following `0.1.22-beta`, available on Yak and GitHub Releases. The resulting `artifacts/better-gh-panel-0.1.23-beta/` contains `manifest.yml`, `icon.png`, `LICENSE`, and the two runtime folders. Packaging validates required assets and rejects unexpected staging-root entries before modifying a previous stage. Yak builds a `better-gh-panel-0.1.23-beta-rh8_0-any.yak` archive there. No command in the packaging script signs in or publishes. `npm run check` runs the core, packaging, and unused-code checks and stages both runtimes locally on Windows or Mac; it does not install or launch Rhino. GitHub Actions CI is disabled.

To install a local package, close Rhino first, then run Yak using the artifact folder as the package source:

```text
yak install --source artifacts/better-gh-panel-0.1.23-beta better-gh-panel 0.1.23-beta
```

Replace `yak` with the full executable path if it is not on PATH. On Windows it is normally `C:\Program Files\Rhino 8\System\Yak.exe`; on Mac it is normally `/Applications/Rhino 8.app/Contents/Resources/bin/yak`. Restart Rhino and open Grasshopper afterward. Local install uses Yak's package directory and avoids copying a second `.gha` into the Grasshopper Libraries folder.

For native validation, run `tests/BetterGhPanel.RhinoSmoke/run.ps1 -PluginPath <extracted net7.0/BetterGhPanel.gha>`. The coordinator stops launching fixtures when an identified Rhino host fails or times out before fixture execution. Its failed outcome retains the startup phase and exception, and the run summary lists every unrun fixture; an incomplete run cannot pass. Failures inside a fixture still allow the remaining fixtures to run. Host reports also record the process ID and actual .NET runtime.

The current native inventory contains 18 focused regressions for capture safety, geometry ownership, reentrant drawing, resource disposal and native clipboard integrity. Routine UI, layout, menu, formatting, selection and general behavior smoke tests have been removed, together with the obsolete diagnostic probes. There is no separate smoke suite. Each remaining fixture starts a fresh Rhino process to isolate native crashes; use `-Fixture <name>` for a targeted check. The historical 66-fixture release results below describe the previous inventory.

If a host fails in `host-startup`, save the run directory and check for a startup dialog or Windows Application Error before rerunning. After saving work and closing interactive Rhino sessions, reproduce just the affected fixture with `run.ps1 -PluginPath <path> -Fixture preview-admission-freshness -TimeoutSeconds 45` (substitute the recorded fixture name). A passing repeat establishes recovery only; it does not establish the earlier cause. Run the complete inventory against the same extracted package before treating validation as complete. Do not change installed runtimes, plug-ins or user settings solely because startup failed.

In Rhino 8's `PackageManager`, enable prereleases to find the beta. For CLI discovery, use `yak search --all --prerelease better-gh-panel`.

The build version lives in `Directory.Build.props`. Packaging fills the `@VERSION@` placeholder in `yak/manifest.yml` and recreates the generated runtime staging directories after verifying the build outputs, so obsolete DLLs cannot enter a rebuilt package. Before a stable release, test Rhino 8 on Windows in both .NET and .NET Framework modes, and on Mac in .NET mode. Verify empty input, mixed/null data, large trees, document removal, saved settings, each tree tool and their combinations, unchanged upstream data, and unchanged typed output with tools off.

Publication was an explicit `yak push` of the validated archive. GitHub releases and future public versions are separate release actions; local build and check scripts never publish automatically.
